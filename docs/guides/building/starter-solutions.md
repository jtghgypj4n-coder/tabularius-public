# Start from a starter solution

Use this guide when a new solution needs a working example of tables, layouts, scripts and value lists before you customize it. It covers choosing a starter and checking the generated design.

1. Pick the starter closest to the task: CRM, inventory, invoicing, tasks or booking.
2. Create the database with `tabularius new`, then set an account password before hosting it.
3. Open the starter in the web client and trace one sample workflow from its layout through its script and related records.
4. Rename or remove sample records before real use. Review the starter's limitations and replace any example policy with the rules your solution needs.

## Worked example

This makes a synthetic task-tracking database with sample records, then prints the design schema. The starter is generated by the CLI and contains no fixture or customer data.

<!-- docs-example: run -->
```sh
tabularius new ~/Databases BuildTasks --starter tasks
tabularius schema ~/Databases BuildTasks --json
```

## Check afterwards

- Confirm the database contains Projects and Tasks and the starter's completion workflow.
- Run `tabularius check-solution ~/Databases BuildTasks` and resolve reported problems.
- Review [starter solutions](../../starter-solutions.md) for included behavior and limitations before adapting the schema.

See [starter solutions](../../starter-solutions.md), [checking a solution](../../check-solution.md), [Design mode](../../design-mode.md), the [REST reference](../../reference/rest.md), and [known differences](../../known-differences.md). Starter contents and tested behavior are Tabularius-specific and do not imply compatibility with a FileMaker template.
