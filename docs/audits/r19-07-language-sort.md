# r19-07: language-aware sorting and Default language

## Already present on this branch

Commit `86b0b341` supplied the [Claris language list and ICU mappings](../sort-languages.md), design mode's Default language selector, language-aware Sort Records and Data API `_sort`, value-list sorting, sub-summary grouping, explicit-locale SortValues, and text find bounds. Those paths were retained. Claris's [SortValues documentation](https://help.claris.com/en/pro-help/content/sortvalues.html) lists the 55 locale names and says locale sorting follows record sorting.

## Work in this item

- SQL `ORDER BY` of a direct text field in one table now uses the same sort key as Sort Records, including `ExecuteSQL` and the read-only SQL connection. Qualified and quoted field names are covered. Expressions, joins and derived tables keep ordinary SQL ordering because there is no single field language to assign without guessing.
- The index-consistency test now checks all 55 offered languages: `<`, `>`, `<=`, `>=` and every generated range are compared with the field's sorted order. The inputs are generated by the test.
- Every locale mapping is labeled "approximation of Claris, unverified" in the language table. Japanese and Chinese special rules remain unverified; Furigana remains "not yet". English and the Unicode options retain their existing order. <!-- known-difference-ok: the registered difference is in docs/sort-languages.md -->

## Compatibility boundary

Claris's [SQL `ORDER BY` reference](https://help.claris.com/en/sql-reference/content/order-by-clause.html) specifies Unicode binary sorting for FileMaker Server. The direct-field SQL behavior here follows the requested cross-surface consistency and therefore intentionally differs from that documented SQL behavior. This is a product choice, not a claim of Claris parity. The ICU approximations have not been compared language by language with FileMaker. Claris also says an omitted SortValues locale uses the file locale; this implementation still uses English when no locale is supplied, because the file locale is not available in the current schema. <!-- known-difference-ok: the registered language and SQL differences are in docs/sort-languages.md -->
